# Omarchy App Submit

Identify the exact destination: official omarchy-pkgs contribution, AUR package, or an independent app directory. These are distinct workflows; do not reuse the Quattro plugin marketplace issue form or Theme Registry form. Read the destination's current instructions, existing entries and required evidence before preparing a body.

Read [packaging workflow](references/packaging.md) for package contributions. Prepare the focused fork/branch diff, source and update provenance, description, licence, architecture coverage, installation behavior and concrete test results. Apply [development handoff](references/handoff.md). Missing live checks stay visible; do not assert official acceptance or readiness from local checks.

For a directory submission, verify the live form/API and media dimensions instead of inventing fields from a previous site. Supply only reviewed public URLs and actual captures. A request to draft a submission does not authorize sending it. If submission is already authorized, proceed without asking again; otherwise show the complete reviewable draft before asking. Do not send unrelated messages, merge a PR, publish a release or operate production infrastructure merely to complete a contributor submission.

## Bundle boundaries

This is part of Build Omarchy Apps, targeting standalone apps on Omarchy 4 / Hyprland. Intended target is not a tested compatibility range. Preserve existing project choices and current user scope. For development PRs/archives, use the handoff guidance where linked; live acceptance, app releases and repository submission remain separate stages.
