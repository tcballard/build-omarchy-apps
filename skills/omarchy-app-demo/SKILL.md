# Omarchy App Demo

Choose one real workflow that communicates the app's current capability. Use fictional accounts/documents and isolated data directories; preserve existing user settings and saves. Prefer deterministic seeds for games and repeatable data for screenshots. Fixture mode must never silently change normal app behavior.

Capture the actual app at a stated commit, Omarchy version, display scale and theme. A design mockup, composited image or contact sheet must be labelled as such and cannot prove desktop integration. Record any staging differences; do not claim a feature works because artwork depicts it.

Verify image/video dimensions and readable content, redact private information, and track each delivered media path with source/licence and purpose. Remove references and credits for excluded assets. Restore temporary changes and perform [development handoff](references/handoff.md) before delivering media in a PR or archive. Use current submission media constraints only if submission is actually in scope.

## Bundle boundaries

This is part of Build Omarchy Apps, targeting standalone apps on Omarchy 4 / Hyprland. Intended target is not a tested compatibility range. Preserve existing project choices and current user scope. For development PRs/archives, use the handoff guidance where linked; live acceptance, app releases and repository submission remain separate stages.
